# PCL.Mac 150 到 156 更新说明

本文用于说明 **PCL.Mac 从 150 到 156** 的主要更新内容。

说明：

- 这里按 **构建号** 整理
- 重点记录用户可感知变化
- 少量纯工程清理内容会简要带过

## 151

- 新增并整理了实例设置侧边栏与相关页面结构，实例设置入口更清晰。
- 新增更新设置页，可以在启动器内查看当前版本、切换更新通道、手动再次检查更新。
- Java 设置页、其他设置页等相关设置页面结构一并整理。

## 152

- 启动器更新系统新增更新用户标识能力，用于后续动态更新与灰度分发。
- 更新设置页补充了用户标识的显示与复制能力，方便联调和排查更新命中情况。

## 153

- Sparkle 更新链路新增频道路由逻辑。
- 更新系统开始支持按频道区分更新来源，为正式版、测试版、灰度测试等通道做准备。

## 154

- Sparkle 频道路由逻辑进一步完善。
- 默认请求频道与相关提示信息得到优化，更新检查行为更加稳定、明确。

## 155

- 清理了旧的测试结果与部分历史产物。
- 这一版主要是内部维护整理，用户侧基本无明显功能变化。

## 156

这是这一段更新里最重要的一版，更新系统整体进入可正式使用状态。

- 更新链路统一为 `https://update.gzitvs.cn` 的 Sparkle 动态 Feed。
- 不再回退旧版 `update.json` 自更新方案，更新逻辑更统一。
- 手动可选更新通道现在只保留：
  - 正式版
  - 测试版
- 测试版更新逻辑改为：
  - 先同时评估 `beta-gray` 与 `beta`
  - 比较两个频道的可升级候选
  - 取版本更高的那个
  - 若版本相同，则优先使用 `beta-gray`
- 修复了旧逻辑里“灰度测试只要有更新就抢占测试版”的问题。
- 更新预评估现在会正确识别并过滤：
  - `minimumUpdateVersion`
  - `minimumSystemVersion`
  - `maximumSystemVersion`
  - `<sparkle:version>`
  - `<enclosure sparkle:version="...">`
- 同一时间只允许一个更新检查流程，避免重复检查时状态串扰。
- 更新用户标识升级为 **安装级匿名 ID**：
  - 首次安装后生成
  - 保存在本地配置
  - 后续更新、替换应用后保持不变
  - 不再依赖普通明文配置值
- 旧的灰度测试手动通道虽然不再可选，但历史配置会自动映射为“测试版”，避免老用户被卡住。

## 一句话总结

从 150 到 156，这一段更新的核心重点是：

- 设置页和实例设置结构更完整
- Sparkle 更新系统逐步接入并完成频道化
- 到 156 时，更新逻辑已经收敛成一套更成熟的正式方案
